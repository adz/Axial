# Axial 0.16.0

Guardrails decide where a raw API may be called with one mechanism: a capability, claimed file by file. A file claims
a capability on its `Compile` item, and only claimed files may call that capability's raw API. Your own capabilities
are defined in small `.capability.toml` files, which a package can ship to everyone who references it. `[boundaries]`
is gone. A rare allowance names the missing feature it stands for, or why the call is deliberate, and policy review
lists each new one first. Policy review now judges capability changes by
direction, so only changes that allow more need a human. AXG001 findings say exactly what to change: the environment
field, the interface, an example call and the test fake.

Full Guardrails checks are faster, and releases ship the analyzer CLI precompiled for linux-x64 and win-x64.
`orDie`, `retryForever`, `Deferred.poll` and `Deferred.make` fit into any workflow without `widenError`, and
`Cache.getSure` reads caches that cannot fail.

## Breaking changes and migration

| Was | Now |
| --- | --- |
| A `capabilities`-role project could make any raw call | a file makes a capability's raw calls only when its `Compile` item claims it: `<Compile Include="Live.fs" AxialCapability="filesystem" />` |
| `[boundaries]` in `Axial.Guardrails.toml` | an error that says what to do instead; delete the section |
| `// axial-allow-AXG001: reason` in a boundary file | claim the capability on the file; otherwise `// axial-allow-AXG001: reason (gap: name)` or `// axial-allow-AXG001: (why: reason)` in any file |
| `// axial-allow-file-AXG001: reason` | claim the capability on the file's `Compile` item |
| `Category` metadata on `AxialGuardrailRule` | ignored; remove it. A rule that a service owns belongs in a capability definition |
| Suppressions for AXG003–AXG008 only in boundary files | in any file; each is still a review item |
| `Deferred.make<'env, 'error, 'value> ()` | `Deferred.make<'env, 'error, 'value, 'workflowError> ()`; type inference usually fills the last parameter |
| `orDie` and `retryForever` returned `Flow<'env, Never, 'value>` | a free error type; drop the `Flow.widenError` that followed them |

To migrate a repository:

1. Run a Full build. Every raw call in a file that is not `host` and claims nothing is now reported.
2. For each file that implements a service, or tests one against the real thing, add `AxialCapability="<name>"` to its
   `Compile` item. `axial capabilities` lists the names. A file compiled into two projects is claimed in each.
3. Remove `axial-allow-AXG001` comments from claimed and `host` files. Rewrite any other call to use the service; keep
   an allowance only for a real missing feature, ending with `(gap: <name>)`, or a deliberate call, ending with
   `(why: <reason>)`.
4. Delete `[boundaries]` from `Axial.Guardrails.toml`; the build fails until you do. A human reviews the change and
   approves the lock once.

## Guardrails

Capabilities:

- **Definitions.** Axial's capabilities are built in: `clock`, `random`, `guid`, `timezone`, `blocking`, `processors`,
  `environment`, `console`, `filesystem`, `process`, `http` and `websocket`. Define your own in a
  `<name>.capability.toml` file with `name`, `service` and `replaces`, plus optional `env`, `field`, `example`, `live`,
  `fake`, `level` and `guardrail`. Name it with `<AxialCapabilityDefinition Include="…" />`. A malformed definition, an
  unknown key, a duplicate name, or an API another capability already covers fails the build with the reason.
- **Claims.** `AxialCapability="name[;name]"` on a `Compile` item. A claimed file may call only the APIs it claims; any
  other raw call in it is reported, with a note saying which capability the file claims. A claim of an undefined
  capability fails the build.
- **Allowances.** `// axial-allow-AXG001: reason (gap: name)` or `// axial-allow-AXG001: (why: reason)` allows one
  call, on its line or the next. AXG002 reports an AXG001 allowance that names neither, any file-wide AXG001
  allowance, and an allowance that allows nothing because a claim, a `host` role or a `forbid` level already decides
  the call. A claim on a file that makes no raw call for that capability is an AXG002 warning. Policy review and the build's drift summary list new AXG001 allowances first, under their own heading.
- **Advice.** A finding names the service, the environment field, the interface, an example call and the test fake.
  For a platform service it says that no environment change is needed and how tests control it. An effect that no
  capability covers offers a definition to write, with the match filled in.
- **Visibility.** `axial capabilities [--json]` lists every capability with the files that claim it. `axial check`
  counts the allowed raw calls per project: in claimed files (per capability), by allowances (per gap, plus a count of whys), and in
  host files (`--json`: `allowedEffects`).

Review by direction:

- The lock records each definition (level and `replaces`) and each project's claimed files.
- Needs review: a definition or `replaces` entry removed, `enforce` lowered to `guide`, a project claiming a
  capability for more files, and, as before, every new suppression.
- Free: a new definition or `replaces` entry, `guide` raised to `enforce`, a claim removed, or a claimed file renamed
  or moved within its project.
- The build's drift warning and `axial policy review`, which gates releases, use the same comparison.

Speed:

- Full mode converts each file's typed tree once and shares it across rules. Effect rules are looked up by type,
  suppression comments are read once per file, and the analyzer CLI runs without dynamic PGO. On Axial's core library
  the Guardrails step of a Full build takes about 10.8 seconds, down from 12.9.
- Release packages carry the analyzer CLI precompiled (ReadyToRun) for linux-x64 and win-x64, which makes Full checks
  about 12 percent faster there. The package grows from about 24 MB to 67 MB. Other platforms, and a runtime major
  version that does not match, use the portable copy.

## Flow

- `Flow.orDie`, `Flow.retryForever` and `Deferred.poll` return a free error type, so they bind in any workflow without
  `widenError`.
- `Deferred.make` takes the creating flow's error as a fourth type parameter, for the same reason.
- `Cache.getSure` reads a cache whose loader cannot fail (`Cache<'key, Never, 'value>`) in any workflow.

## Fixes

- Axial, Axial.HttpClient, Axial.Process and Axial.Hosting.GenHttp work in `dotnet fsi` from Debug builds. Their
  `task` blocks disposed resources through `TaskBuilderBase.Using`, which the FSharp.Core in `dotnet fsi` lacks; they
  now dispose with `try/finally`.
