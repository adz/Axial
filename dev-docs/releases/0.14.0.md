# Axial 0.14.0

`Axial.ElmishFlows` now lets an inbox be built in the scope that shuts it down. `Inbox.scopedWith` takes a
`QueueStrategy`, and `scopedSliding`, `scopedDropping`, `scopedBounded` and `scopedUnbounded` name the four strategies,
so the overflow policy is chosen where the inbox is created instead of being implied by a runtime call. A layer passed to
`ElmishRuntime.startLayer` is provisioned in the runtime's root scope, so an inbox built there can be an ordinary
environment field: it lives as long as the program, is shut down with the runtime, and needs no later registration step
that could leave an unshut inbox representable. `Inbox.create capacity runtime` remains for a host that already holds the
runtime, and the [Inbox API page](/elmish/api/Axial.ElmishFlows.Inbox.html) documents every constructor and how a dropped
offer is counted.
