# Axial 0.17.0: concurrency laws, progress line by line

A new torture scenario generates random compositions of fork, race, zipPar, scopes, timeouts and interruption and
checks the concurrency laws on each. It found two runtime bugs, both fixed here. Process lines now end where .NET
ends them, so progress output streams as it is drawn, and two small additions let an application drop exceptions it
had to keep under 0.16.

## Fixes

- **A timeout, race or zipPar can stop a flow that is waiting in `Fiber.join`.** A fiber forked inside one of them
  follows the token outside it, so that it can outlive the branch when the caller keeps its value. Only its scope's
  close would interrupt it, and that scope could not close while the join ignored the branch's interruption: a
  timeout around a scoped fork-and-join of a fiber that never ended hung forever. Interrupting the joining flow now
  stops the wait, not the fiber, as the `awaitExit` docs already promised; the fork's scope then interrupts the child.
  A join that gives up does not consume the outcome, so a defect the fiber settles with later is still reported as
  unobserved. A join under the token the fiber follows (the usual fork then join in one flow) takes the old path,
  so fork/join costs the same: 4.29 µs before and 4.32 µs after for a trivial fork/join, with the same allocation.
- **An unjoined fiber that dies with several defects reports each one.** Only the first defect of a compound cause
  was reported as unobserved; the rest were lost. This happened when `recover` turned a race winner's typed failure
  into a defect beside the loser's.
- `Axial.ElmishFlows`: a command or service job interrupted by the runtime stopping now stops its fiber and takes its
  outcome, so a defect from the fiber's cleanup still reaches `OnDefect`. It relied on the old join behaviour.

## Torture tests

- The `laws` scenario builds 40 random trees per round from leaves that succeed, fail, die or hang, combined with
  `Flow.fork` (then join, interrupt or abandon), `race`, `zipPar`, a scoped resource, `recover`, `fold`, `timeout`
  and an interrupted fiber. Every tree must keep six laws: a flow that starts work waits for it; a race's loser
  settles before the race returns; interrupting a fiber waits for it to end; cleanup runs exactly once, after its
  acquire; every defect is reported exactly once; interruption is never swallowed by `recover` or `fold`. A broken
  law prints the tree that broke it. It runs on .NET and on Node.

## Flow

- `Parallelism.count` reads back the bound a `Parallelism` was made with. Code that divides work itself, such as one
  chunk per worker, can size it from the machine without reading `Environment.ProcessorCount`, so no file needs to
  claim the `processors` capability:

  ```fsharp
  let workers = Parallelism.ofProcessors (fun n -> Math.Clamp(n / 2, 1, 4)) |> Parallelism.count
  ```

## Diagnostics

- `UnobservedDefect` gains `At`, when the defect was reported. Installed with `Flow.withFiberRegistry`, the registry
  reads it from the runtime's clock, so it is the test clock under `Flow.runTest`; `registry.Observer` composed by hand
  reads the system clock. A diagnostics screen no longer needs its own clock to timestamp a defect that arrived outside
  any flow.

## Process

- Line framing ends a line at a bare CR as well as at LF and CRLF, as `StreamReader.ReadLine` does. Progress output
  (`git --progress`, `curl`) redraws one line by ending it with a bare CR. Before, a run of redraws stayed one line until
  the final LF, so nothing streamed while it ran and a long run could fail with `LineTooLong`. Each redraw now arrives
  as its own line when it is written. `mergeStdout` forwards a bare CR as a line boundary too.
- `ProcessOutput.Ending` says how a line ended: `LineEnding.Lf`, `CrLf`, `Cr`, or `EndOfOutput`. A display replaces
  the line after a `Cr` line rather than adding it, and text plus ending rebuilds the output exactly. Chunks have
  `Ending = None`.

## Guardrails

- The `environment.processor-count` finding names `Parallelism.count` alongside `Parallelism.ofProcessors`.

## Breaking changes and migration

- `UnobservedDefect` has a new field. Code that only reads registry results is unaffected; code that constructs an
  `UnobservedDefect` record adds `At`.
- Line framing splits at a bare CR. Code that expected `"a\rb"` as one line now gets `"a"` then `"b"`; use chunk
  framing (`streamStdout`) or the captured output to keep a CR inside the text.
- `ProcessOutput` has a new field, `Ending`. Code that constructs one, such as a fake process service, adds it.
- Interrupting a flow that waits in `Fiber.join` or `Fiber.awaitExit` stops the wait instead of waiting for the fiber
  to end. Code that relied on the wait continuing, for example to collect a defect from the fiber's cleanup after
  being interrupted, stops the fiber with `Fiber.interrupt` and reads the exit it returns, as `Axial.ElmishFlows` now does.
