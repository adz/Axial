# Axial 0.11.0 (draft)

This release ties scoped resources in concurrent code to the values that carry them, makes recursive flows run in
constant memory on .NET, and rebuilds `Axial.Process` around commands, independent capture policies, and
completion-aware streams. It also adds test doubles for every operational service, .NET interop bridges, and more STM
collections.

Concurrent combinators now treat scoped resources this way:

- When you receive a concurrent flow's value, you also receive its scoped resources.
- When you don't receive the value, its scoped resources are released.

A scoped resource is anything registered with a Flow scope, such as a value from `Flow.scopeResource` or a hub
subscription.

## Breaking changes

`Axial.Process`:

| Before | Now |
| --- | --- |
| `ProcessError.TimedOut` | `ProcessError.StageTimedOut` for one command and `ProcessError.OverallTimedOut` for the whole topology; `ProcessError.exitCode` returns 124 for both |
| `Process.stream` and `ProcessEvent` | `Process.streamOutputs`, `streamStdout`, `streamStderr`, `streamStdoutLines`, and `streamStderrLines`, which return a completion-aware `ProcessStream`; `ProcessStream.toFlowStream` converts one to a `FlowStream` and drops completion |
| `IProcess.Run` and `IProcess.Stream` | `IProcess.Execute` |
| `Process.run` and `runWith` return an exit code and print the failure to the console | `run` and `runWith` accept a command, spec, or flow, return its value, and raise `ProcessRunException` on failure; `tryRun` and `tryRunWith` return the `Exit` |
| `Output.capture`, `Output.captureTail`, `OutputTarget.Capture`, `OutputTarget.CaptureTail` | Capture is separate from routing: `Process.captureAll`, `captureTail`, and `captureNothing` for stdout, and `captureStderr*` for stderr |
| `writeTo`, `appendTo` | `Process.stdoutToFile`, `stdoutToAppendFile`, and the other `stdoutTo*` routes, followed by an explicit runner |
| `Input.read` / `InputSource.Read` | `Input.readOnce` / `InputSource.ReadOnce` |
| Command settings on `ProcessSpec` | `ProcessCommand` holds a command's settings and `ProcessSpec` holds connections; `mapFinalCommand` changes the final command of an assembled pipeline |

`Process.toFlow` now keeps unmerged stderr as a 64 KiB tail for each readable stage instead of capturing it in full.
`Process.captureStderrAll` restores full stderr transcripts.

## Behaviour changes

- Direct tail-recursive `flow { ...; return! loop () }` workflows run in constant memory on .NET when completed
  iterations have no pending work or lexical cleanup. Previously each asynchronous iteration retained a task until the
  whole loop completed. `Flow.bind` and `Flow.delay` now trampoline these continuations. Fable already ran them in
  constant memory.
- `Flow.zipPar`, `Flow.sequencePar`, `Flow.traversePar`, and `Flow.forEachPar` run each flow in its own scope. When every
  flow succeeds, what they acquired moves to the caller's scope, as before. When any flow fails, everything the flows
  acquired is released before the combinator returns, instead of when the caller's scope closes.
- `Flow.race` keeps the winner's scoped resources when it succeeds and releases the loser's once it has been
  interrupted, instead of keeping both until the caller's scope closes.
- `Flow.timeout`, `Flow.timeoutToOk`, and `Flow.timeoutWith` release a timed-out or failed flow's scoped resources before
  returning or running the fallback.
- `Flow.traversePar` and `Flow.forEachPar` keep what each item acquired after its worker finishes. Previously an item's
  scoped resources were released when its worker ran out of values, so they could be gone before the traversal
  returned. The per-worker resource of `traverseParUsing` and `forEachParUsing` is still released when the worker
  finishes.
- A process stage deadline starts when that stage launches, not when the topology starts.

## New

- `Flow.forkResource resource` acquires a `Resource` in a fiber and registers its release with the caller's scope, so
  `Fiber.join` returns a live resource. Use it where ZIO code would `fork` an `acquireRelease` and `join` it later; a
  plain `Flow.fork` releases what the fiber acquired when the fiber settles.
- `Axial.Guardrails` reports `AXG007` (`ResourceFromFiber`) for a forked flow that returns a scoped resource it
  acquired itself, which the fiber releases before `Fiber.join` returns it.
- Process:
  - `ProcessStream` reports how a process ended alongside its output: `Completed` with the result, or
    `StoppedEarly` after a consumer stops and cleanup finishes.
  - Line streams keep blank and final unterminated lines and fail with `LineTooLong` past `Process.maxLineLength`
    (1,048,576 characters by default).
  - `Process.stageDefaults` sets defaults for every stage that explicit command settings override.
  - `Process.renderPlan` prints a plan as short lines without starting a process.
- Test doubles:
  - `Console.test`, `FileSystem.test`, `Http.test`, and `Process.test`.
  - `Log.capturing`, `Random.fromSequence`, and `Guid.fromSequence`.
  - `TestRuntime`, which bundles a manual clock, a recording log, and scripted random, GUID, and environment services
    into one environment.
- Interop:
  - `FlowStream.ofAsyncEnumerable` reads any `IAsyncEnumerable`, including `ChannelReader.ReadAllAsync`.
  - `Clock.fromTimeProvider` and `Clock.toTimeProvider` bridge to .NET `TimeProvider`.
  - `Configuration.environmentVariables` adapts `IConfiguration`, and `HttpFactory.live` adapts `IHttpClientFactory`.
  - `Deferred.fromTask` and `Deferred.toTask` bridge tasks; `SemaphoreSlim.acquire`, `release`, and `withPermit` gate
    flows on a BCL semaphore.
  - `Metrics.counter`, `histogram`, and `gauge` create `System.Diagnostics.Metrics` instruments, and `Metrics.add` and
    `Metrics.record` emit values from a flow.
- STM: `TRef.modify`, `getAndSet`, `getAndUpdate`, and `updateAndGet`, and the `TQueue`, `TSemaphore`, and `TPromise`
  collections.

## Fixes

- `FlowStream.ofAsyncEnumerable` creates its enumerator on each run and disposes it when a run is cut short.
- `TQueue` and `TSemaphore` reject a non-positive capacity or negative permits instead of creating an unusable value.
- The test file system's `AppendAllLines` ends each line with a newline, as `System.IO.File.AppendAllLines` does.
- Process failures keep their original cause through stream cleanup.
- A keyed fiber slot drops its fiber once the fiber settles, however quickly that happens.
- The Fable build compiles again after the Process file split.
