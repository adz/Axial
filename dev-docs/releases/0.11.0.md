# Axial 0.11.0 (draft)

This release ties scoped resources in concurrent code to the values that carry them, makes recursive flows run in
constant memory on .NET, and rebuilds `Axial.Process` around commands, independent capture policies, and
completion-aware streams. It also adds test doubles for every operational service, .NET interop bridges, and more STM
collections.

Concurrent combinators now treat scoped resources this way:

- When you receive a concurrent flow's value, you also receive its scoped resources.
- When you don't receive the value, its scoped resources are released.

A scoped resource is anything registered with a Flow scope, such as a value from `Flow.scopeResource` or a hub
subscription.

## Breaking changes

`IFileSystem` async read, write, and append members now return `Flow<unit, FileSystemError, 'value>` instead of `Task` and no longer take a cancellation token. The flow uses its runtime token; missing files are typed failures and cancellation interrupts.

`IHttp.Send` now takes only an `HttpRequest` and returns `Flow<unit, HttpError, HttpResponse>`; implementations return typed HTTP failures through the flow, while cancellation interrupts it.

Resource release is a flow. A release is `'value -> Flow<'env, Never, unit>`: it runs without interruption, with the
environment captured when the value was acquired, and in a scope of its own that closes after it. It cannot fail with a
typed error; a release that throws or dies is a defect of the flow that closed the scope, after the scope's other
releases have run. Cleanup can therefore update a `Ref` or call a service from the environment.

| Before | Now |
| --- | --- |
| `Resource.create acquire (fun value cancellationToken -> task)` | `Resource.create acquire (fun value -> releaseFlow)` |
| `Resource.ofAsync acquire (fun value cancellationToken -> async)` | Removed; use `Resource.create` with `Flow.fromAsync` |
| `Resource.finalizer (fun cancellationToken -> task)` | `Resource.finalizer releaseFlow` |
| `Resource.asyncFinalizer` | Removed; use `Resource.finalizer` |
| `Flow.scopeAcquireRelease acquire (fun value cancellationToken -> task)` | `Flow.scopeAcquireRelease acquire (fun value -> releaseFlow)` |
| `Flow.scopeFinalizer (fun cancellationToken -> task)` | `Flow.scopeFinalizer releaseFlow` |
| `Flow.scopeAsyncFinalizer` | Removed; use `Flow.scopeFinalizer` |
| A release saw the closing scope's cancellation token | A release runs without interruption; `Flow.cancellationToken` inside it is never cancelled |

`Resource.create`, `Resource.finalizer`, `Flow.scopeAcquireRelease`, and `Flow.scopeFinalizer` are now available on
Fable.

Release cost was recovered without changing release execution. On the isolated .NET `ScopeCloseBenchmarks` run
(per 1000 scopes, mean / allocated), the T1b starting point and final measurement were:

| Case | T1b before | T1b after |
| --- | ---: | ---: |
| Empty close | 425.4 μs / 790.55 KB | 411.1 μs / 782.40 KB |
| Acquire/release | 1116.3 μs / 2048.37 KB | 891.7 μs / 1571.47 KB |
| One finalizer | 1166.9 μs / 2103.06 KB | 920.9 μs / 1626.15 KB |

A scope uses itself as its lock, stores a single finalizer without a dictionary, and avoids the multi-finalizer
execution state machine on .NET and the sorting path when closing one finalizer. Fable keeps its existing
finalizer trampoline. A release still receives a new runtime and
scope, and switches the ambient runtime: skipping that switch based on synchronous completion cannot establish
whether the release read the ambient runtime. Parallel composition allocations remained within the pre-T1b range.

`Axial.Layers`:

| Before | Now |
| --- | --- |
| `Layer.fromAsync`, `Layer.fromTask`, `Layer.fromValueTask`, which passed the raw `Scope` and expected a hand-built `Exit` | Removed; use `Layer.fromFlow`, which runs a flow in the layer's scope |
| `Layer.acquireRelease acquire (fun resource cancellationToken -> task)` | `Layer.acquireRelease acquire (fun resource -> releaseFlow)`, where the release reads the layer's input as its environment |
| `Layer.addFinalizer (fun cancellationToken -> task)` | `Layer.addFinalizer releaseFlow` |

`Axial.Process`:

- `Process.maxOutputBytes stdout stderr` (also in the DSL) fails with `OutputTooLarge` when a redirected original output channel exceeds its total byte cap, regardless of framing or capture. It kills managed stages and attempts to kill their descendants; a descendant reparented after its parent exits may survive, but closed pipe ends prevent it from blocking cleanup. Caps on inherited channels are rejected.

| Before | Now |
| --- | --- |
| `ProcessError.TimedOut` | `ProcessError.StageTimedOut` for one command and `ProcessError.OverallTimedOut` for the whole topology; `ProcessError.exitCode` returns 124 for both |
| `Process.stream` and `ProcessEvent` | `Process.streamOutputs`, `streamStdout`, `streamStderr`, `streamStdoutLines`, and `streamStderrLines`, which return a completion-aware `ProcessStream`; `ProcessStream.toFlowStream` converts one to a `FlowStream` and drops completion |
| `IProcess.Run` and `IProcess.Stream` | `IProcess.Execute` |
| `Process.run` and `runWith` return an exit code and print the failure to the console | `run` and `runWith` accept a command, spec, or flow, return its value, and raise `ProcessRunException` on failure; `tryRun` and `tryRunWith` return the `Exit` |
| `Output.capture`, `Output.captureTail`, `OutputTarget.Capture`, `OutputTarget.CaptureTail` | Capture is separate from routing: `Process.captureAll`, `captureTail`, and `captureNothing` for stdout, and `captureStderr*` for stderr |
| `writeTo`, `appendTo` | `Process.stdoutToFile`, `stdoutToAppendFile`, and the other `stdoutTo*` routes, followed by an explicit runner |
| `Input.readOnce`, `Input.produce` / `InputSource.ReadOnce`, `Produce` | `Input.flowStream` / `InputSource.Stream` (environment-free byte stream) |
| Async `Output.callback`, `OutputTarget.Sink`, `SinkFactory` | Flow callbacks and completion flows; typed failures become `ProcessError.OutputFailed`, defects remain defects |
| `AspNetCore.handleParsed`, `GenHttp.handleParsed` | Removed; use the Flow endpoint APIs |
| Command settings on `ProcessSpec` | `ProcessCommand` holds a command's settings and `ProcessSpec` holds connections; `mapFinalCommand` changes the final command of an assembled pipeline |

Stream input typed failures become `ProcessError.InputFailed` (AOT-safe rendered cause); cancellation remains interruption. Close over application dependencies with `Flow.localEnv` (or `Layer.provide`) before constructing a process spec.

`Process.toFlow` now keeps unmerged stderr as a 64 KiB tail for each readable stage instead of capturing it in full.
`Process.captureStderrAll` restores full stderr transcripts.

The ASP.NET Core and GenHTTP HTTP adapters, their integration tests, and examples now build against Reified 0.10.0 from NuGet. The discontinued `Reified.Schema.Json` package is no longer required; JSON codecs ship in `Reified.Schema`. AXG005 cancellation-token fixes pass the HTTP request token explicitly to form parsing and keep cancellation at the runtime boundary.

## Behaviour changes

- Direct tail-recursive `flow { ...; return! loop () }` workflows run in constant memory on .NET when completed
  iterations have no pending work or lexical cleanup. Previously each asynchronous iteration retained a task until the
  whole loop completed. `Flow.bind` and `Flow.delay` now trampoline these continuations. Fable already ran them in
  constant memory.
- `Flow.zipPar`, `Flow.sequencePar`, `Flow.traversePar`, and `Flow.forEachPar` run each flow in its own scope. When every
  flow succeeds, what they acquired moves to the caller's scope, as before. When any flow fails, everything the flows
  acquired is released before the combinator returns, instead of when the caller's scope closes.
- `Flow.race` keeps the winner's scoped resources when it succeeds and releases the loser's once it has been
  interrupted, instead of keeping both until the caller's scope closes.
- `Flow.timeout`, `Flow.timeoutToOk`, and `Flow.timeoutWith` release a timed-out or failed flow's scoped resources before
  returning or running the fallback.
- `Flow.traversePar` and `Flow.forEachPar` keep what each item acquired after its worker finishes. Previously an item's
  scoped resources were released when its worker ran out of values, so they could be gone before the traversal
  returned. The per-worker resource of `traverseParUsing` and `forEachParUsing` is still released when the worker
  finishes.
- A process stage deadline starts when that stage launches, not when the topology starts.

## New

- `Cache.makeBounded` retains at most a specified number of keys with LRU eviction; `Cache.makeBoundedWithExpiry` refreshes successes after a monotonic-clock TTL. `Cache.makeRec` lets lookups read other keys through the same cache; cyclic reads deadlock.

- `Flow.recover` handles a single typed failure with a fallback that may change the error type; defects and interruptions remain unhandled. Compound causes are not recovered; their typed failures become defects when retyped.

- `FlowStream.fromCallback capacity subscribe` bridges synchronous callbacks into a bounded stream. `fromCallbackWith capacity (CallbackOverflow.Fail error) subscribe` instead fails the stream on overflow; the default `CallbackOverflow.Dropping` drops newest values (reported by `Emit.Value`). Subscription disposal is scope-owned.

- `Layer.fromFlow build` builds a layer's output by running a flow with the layer's input as its environment. The flow
  runs in the layer's scope, so what it acquires with `Flow.scopeAcquireRelease` or `Flow.scopeFinalizer` stays open
  until `Layer.provide` finishes and is released in reverse order.
- `Flow.forkResource resource` acquires a `Resource` in a fiber and registers its release with the caller's scope, so
  `Fiber.join` returns a live resource. Use it where ZIO code would `fork` an `acquireRelease` and `join` it later; a
  plain `Flow.fork` releases what the fiber acquired when the fiber settles.
- `Axial.Guardrails` exempts completed-task result reads guarded by the same task's completion state and result reads on `ContinueWith` continuation parameters.
- `Axial.Guardrails` flags blocking waits outside flows (`Async.RunSynchronously`, `Task.Wait`, task/value-task `.Result`, task awaiter `.GetResult`) and direct `Flow.run`/`runSync`/`RunSynchronously`/`StartAsTask` calls returning a scope-owned `Cache`, `Hub`, or `Queue`. Genuine boundaries can allow blocking with `axial-allow-effect: blocking`.
- `Axial.Guardrails` flags `TimeZoneInfo.Local` under the `Axial.PlatformService` environment guardrail; pass an explicit time zone for conversions.
- `Axial.Guardrails` reports `AXG007` (`ResourceFromFiber`) for a forked flow that returns a scoped resource it
  acquired itself, which the fiber releases before `Fiber.join` returns it.
- Process:
  - `ProcessStream` reports how a process ended alongside its output: `Completed` with the result, or
    `StoppedEarly` after a consumer stops and cleanup finishes.
  - Line streams keep blank and final unterminated lines and fail with `LineTooLong` past `Process.maxLineLength`
    (1,048,576 characters by default).
  - `Process.stageDefaults` sets defaults for every stage that explicit command settings override.
  - `Process.renderPlan` prints a plan as short lines without starting a process.
- Test doubles:
  - `Console.test`, `FileSystem.test`, `Http.test`, and `Process.test`.
  - `Log.capturing`, `Random.fromSequence`, and `Guid.fromSequence`.
  - `TestRuntime`, which bundles a manual clock, a recording log, and scripted random, GUID, and environment services
    into one environment.
- Interop:
  - `FlowStream.ofAsyncEnumerable` reads any `IAsyncEnumerable`, including `ChannelReader.ReadAllAsync`.
  - `Clock.fromTimeProvider` and `Clock.toTimeProvider` bridge to .NET `TimeProvider`.
  - `Configuration.environmentVariables` adapts `IConfiguration`, and `HttpFactory.live` adapts `IHttpClientFactory`.
  - `Deferred.fromTask` and `Deferred.toTask` bridge tasks; `SemaphoreSlim.acquire`, `release`, and `withPermit` gate
    flows on a BCL semaphore.
  - `Metrics.counter`, `histogram`, and `gauge` create `System.Diagnostics.Metrics` instruments, and `Metrics.add` and
    `Metrics.record` emit values from a flow.
- STM: `TRef.modify`, `getAndSet`, `getAndUpdate`, and `updateAndGet`, and the `TQueue`, `TSemaphore`, and `TPromise`
  collections.

## Fixes

- Guardrails findings now fail the build with an `AXG` diagnostic and a findings summary instead of an `MSB3073` CLI exit-code message. Other non-zero CLI exits report a tool failure.

- On .NET, `App.start` runs the root off the caller's synchronization context. `AppHandle.StopAndWait(timeout)` requests stop and blocks until finalizers finish or the timeout expires, including on UI threads.

- `FlowStream.ofAsyncEnumerable` creates its enumerator on each run and disposes it when a run is cut short.
- `TQueue` and `TSemaphore` reject a non-positive capacity or negative permits instead of creating an unusable value.
- The test file system's `AppendAllLines` ends each line with a newline, as `System.IO.File.AppendAllLines` does.
- Process failures keep their original cause through stream cleanup.
- A keyed fiber slot drops its fiber once the fiber settles, however quickly that happens.
- The Fable build compiles again after the Process file split.

## Documentation

- The type troubleshooting guide shows how to avoid FS0030 for a generic environment flow by defining a type function instead of a value.

- The scopes guide explains how a release runs. Its examples, and those in the fibers, semaphore, cache, and
  supervision guides, record state in a `Ref` instead of a lock or `Interlocked`.
- The layers guide, its tutorial, and the hosting and platform-service layers use `Layer.fromFlow`.
- The scopes guide defines scoped resources and has a section on concurrency and scoped resources, with a table of
  what each combinator does and a note for readers coming from ZIO or Effect. The fibers guide describes the same
  behaviour where `fork` and the parallel combinators are introduced, and `llms.txt` covers it too.
- The process guides are rewritten around commands, capture, completion-aware streams, and runners, with checked
  recipes for the DSL.
- The Flow type guide explains which recursive flows run in constant memory.

### Axial.Elmish

Added a per-program Elmish runtime with host-posted delivery, keyed latest-wins commands, stream subscriptions, bounded inboxes, and a queued test runtime. Inbox construction no longer starts a separate blocking application.

### Axial.Files

Added breadth-first `Files.walk` and batched, BOM-aware `Files.lines` over `IFileSystem`. Added recursive `Files.watch` with a mockable watcher, typed errors, and fail-on-overflow buffering. Added `Files.writeAtomic` and text variants with same-directory temporary writes, data flush, and overwrite rename (no directory fsync). Added `AppendLog`, a bounded two-file framed log with CRC32, flush-before-acknowledgement, torn-tail recovery, rotation, and ordered replay.
