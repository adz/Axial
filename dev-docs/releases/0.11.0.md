# Axial 0.11.0

Scoped resources now follow the values returned by concurrent flows, and releases are flows themselves. File-system and HTTP services return flows instead of tasks. This release adds Axial.Files, Axial.ElmishFlows, and Axial.WebSocket, along with Elmish and desktop hosting support. Guardrails adds rules for blocking calls and escaped scoped resources. Packages now publish Experimental or Incubating maturity ratings; none is Stable.

## Upgrading

If new AXG001 or AXG008 findings fail your build, run `dotnet build -p:AxialGuardrailsSeverity=warning` (or `dotnet test` with the same property), or set `AXIAL_GUARDRAILS_SEVERITY=warning` while fixing them. The project property or `-p:` setting takes precedence. Move effects behind services or mark genuine boundaries, then restore error severity.

- Convert resource and layer releases to flows; replace removed async constructors and finalizers.
- Update `IFileSystem` and `IHttp.Send` implementations and callers to use flows and runtime cancellation.
- Migrate Process specs to commands, `IProcess.Execute`, explicit capture/routing, completion-aware streams, and the new runners and timeout errors.
- Replace HTTP adapters' `handleParsed` with Flow endpoints; update Reified dependencies.
- Review Guardrails findings for blocking calls and scope-owned values escaping a run.

## Breaking changes

### Axial and Axial.Layers

A release is `'value -> Flow<'env, Never, unit>`. It runs without interruption using the environment captured at acquisition, in its own scope, which closes afterward. It cannot fail with a typed error; a thrown exception or death becomes a defect of the closing flow after other releases run. Cleanup can update a `Ref` or use an environment service. `Flow.cancellationToken` in a release is never cancelled.

| Before | Now |
| --- | --- |
| `Resource.create acquire (fun value cancellationToken -> task)` | `Resource.create acquire (fun value -> releaseFlow)` |
| `Resource.ofAsync acquire (fun value cancellationToken -> async)` | Removed; use `Resource.create` and `Flow.fromAsync` |
| `Resource.finalizer (fun cancellationToken -> task)` | `Resource.finalizer releaseFlow` |
| `Resource.asyncFinalizer` | Removed; use `Resource.finalizer` |
| `Flow.scopeAcquireRelease acquire (fun value cancellationToken -> task)` | `Flow.scopeAcquireRelease acquire (fun value -> releaseFlow)` |
| `Flow.scopeFinalizer (fun cancellationToken -> task)` | `Flow.scopeFinalizer releaseFlow` |
| `Flow.scopeAsyncFinalizer` | Removed; use `Flow.scopeFinalizer` |

These resource and scope APIs are now available on Fable. In `Axial.Layers`, `Layer.fromAsync`, `fromTask`, and `fromValueTask` (which exposed a raw `Scope` and required a hand-built `Exit`) are removed; use `Layer.fromFlow`. `Layer.acquireRelease` now takes `fun resource -> releaseFlow`, whose environment is the layer input; `Layer.addFinalizer` takes a release flow instead of a token-to-task function.

### Axial.FileSystem and Axial.HttpClient

`IFileSystem` async read, write, and append members return `Flow<unit, FileSystemError, 'value>` instead of `Task` and no longer take a cancellation token. Missing files are typed failures; runtime cancellation interrupts. `IHttp.Send` takes only an `HttpRequest` and returns `Flow<unit, HttpError, HttpResponse>`; HTTP failures are typed and cancellation interrupts.

### Axial.Process

`ProcessCommand` holds command settings; `ProcessSpec` holds connections. `Process.mapFinalCommand` changes the final command of a pipeline. `IProcess.Run` and `Stream` are replaced by `IProcess.Execute`. `Process.run` and `runWith` accept a command, spec, or flow, return its value, and raise `ProcessRunException` on failure instead of returning an exit code and printing the failure; `tryRun` and `tryRunWith` return the `Exit`.

| Before | Now |
| --- | --- |
| `ProcessError.TimedOut` | `StageTimedOut` or `OverallTimedOut`; both map to exit code 124 |
| `Process.stream`, `ProcessEvent` | `streamOutputs`, `streamStdout`, `streamStderr`, `streamStdoutLines`, `streamStderrLines` returning `ProcessStream`; `ProcessStream.toFlowStream` drops completion |
| `Output.capture`, `captureTail`, `OutputTarget.Capture`, `CaptureTail` | `Process.captureAll`, `captureTail`, `captureNothing` for stdout, and `captureStderr*` for stderr, independent of routing |
| `writeTo`, `appendTo` | `Process.stdoutToFile`, `stdoutToAppendFile`, and other `stdoutTo*` routes, then an explicit runner |
| `Input.readOnce`, `Input.produce`, `InputSource.ReadOnce`, `Produce` | `Input.flowStream` / `InputSource.Stream` (environment-free byte stream) |
| Async `Output.callback`, `OutputTarget.Sink`, `SinkFactory` | Flow callbacks and completion flows; typed failures become `OutputFailed`, defects remain defects |

Stream input typed failures become `ProcessError.InputFailed` with an AOT-safe rendered cause; cancellation interrupts. Close over application dependencies with `Flow.localEnv` or `Layer.provide` before building a spec. `Process.maxOutputBytes stdout stderr` (also in the DSL) caps each redirected original output channel's total bytes independently of framing or capture and fails with `OutputTooLarge`; inherited channels cannot be capped. It kills managed stages and attempts to kill descendants. A descendant reparented after its parent exits may survive, but closed pipe ends prevent it from blocking cleanup. `Process.toFlow` keeps an unmerged 64 KiB stderr tail per readable stage rather than full stderr; `Process.captureStderrAll` restores full transcripts.

### HTTP host adapters

`AspNetCore.handleParsed` and `GenHttp.handleParsed` are removed; use Flow endpoints. The ASP.NET Core and GenHTTP adapters, integration tests, and examples use Reified 0.10.0 from NuGet. `Reified.Schema.Json` is no longer needed: JSON codecs ship in `Reified.Schema`. Form parsing passes the HTTP request token explicitly to satisfy AXG005 and retains cancellation at the runtime boundary.

## New packages

**Axial.Files — Incubating.** `Files.walk` traverses breadth-first; `Files.lines` reads BOM-aware batches through `IFileSystem`. Recursive `Files.watch` streams `FileSystemChange` with a mockable watcher, typed errors, and fail-on-overflow buffering. `Files.writeAtomic` and text variants write a same-directory temporary file, flush data, and rename with overwrite (without directory fsync). `AppendLog` is a bounded, two-file framed log with CRC32, flush-before-acknowledgement, torn-tail recovery, rotation, and ordered replay.

**Axial.ElmishFlows — Incubating.** Its per-program Elmish runtime supports host-posted delivery, keyed latest-wins commands, stream subscriptions, bounded inboxes, and a queued test runtime. The unpublished `Axial.Elmish` package was renamed to match its namespace: opening `Axial` previously made `Axial.Elmish` shadow the consuming app's Elmish namespace. Inbox construction no longer starts a separate blocking application. `ElmishRuntime.startLayer` provisions resources in the runtime root scope until `Stop`/`StopAndWait`; a typed provisioning failure returns `Error` and starts nothing. `Cmd.OfFlow.start name runtime workflow` runs a named `Flow<'env, Never, unit>` fiber without dispatch, reporting defects to `OnDefect`. Command order is `name runtime workflow onSuccess onError` (positional, not piped); the namespace-coexistence test also exercises Elmish `Sub.none`/`Sub.batch` beside `Sub.OfFlowStream.subscribe`.

**Axial.WebSocket — Experimental.** A .NET client service provides scoped sessions, text and binary messages, and a scripted test double. On .NET 8 it supports client certificates, custom-root-only trust, minimum TLS version, transport connect hooks, and wire byte counting.

## New APIs

### Axial, Axial.Layers, and Axial.State

- `Cache.makeBounded` limits keys with LRU eviction; `makeBoundedWithExpiry` refreshes successes after a monotonic-clock TTL. `Cache.makeRec` allows lookups across keys in the same cache; cyclic reads deadlock.
- `Flow.recover` handles one typed failure with a fallback that may change error type. Defects and interruptions are not recovered; typed failures in compound causes become defects when retyped.
- `Flow.forkResource` acquires a `Resource` in a fiber and registers release with the caller's scope, so `Fiber.join` returns a live resource. Plain `Flow.fork` releases acquisitions when its fiber settles.
- `FlowStream.reissueOnWake` starts immediately and interrupts and restarts on each wake. Wake interruptions do not use retry attempts; typed failures propagate. `FlowStream.fromCallback capacity subscribe` bridges synchronous callbacks into a bounded stream: default `CallbackOverflow.Dropping` drops newest values (reported by `Emit.Value`), while `fromCallbackWith capacity (CallbackOverflow.Fail error) subscribe` fails on overflow. Disposal belongs to the scope.
- `FiberLocal.make` and `named` create scoped values inherited by forks; `locally` restores the prior value afterward. The Microsoft logging adapter scopes explicitly set named values on log entries, including fiber defect logs.
- `Layer.fromFlow` runs a build flow with the layer input in the layer scope; its acquisitions and finalizers remain until `Layer.provide` finishes, then release in reverse order. `App.startWith` publishes services from a root scope alive until its handle stops.
- Test doubles: `Console.test`, `FileSystem.test`, `Http.test`, `Process.test`, `Log.capturing`, `Random.fromSequence`, `Guid.fromSequence`; `TestRuntime` bundles manual clock, recording log, and scripted random, GUID, and environment services.
- Interop: `FlowStream.ofAsyncEnumerable` accepts `IAsyncEnumerable`, including `ChannelReader.ReadAllAsync`; `Clock.fromTimeProvider`/`toTimeProvider`, `Configuration.environmentVariables` for `IConfiguration`, `HttpFactory.live` for `IHttpClientFactory`, `Deferred.fromTask`/`toTask`, and `SemaphoreSlim.acquire`/`release`/`withPermit`. `Metrics.counter`/`histogram`/`gauge` create `System.Diagnostics.Metrics` instruments; `Metrics.add`/`record` emit from flows.
- STM adds `TRef.modify`, `getAndSet`, `getAndUpdate`, `updateAndGet`, and `TQueue`, `TSemaphore`, and `TPromise`.

### Axial.Process

`ProcessStream` reports `Completed` with the result or `StoppedEarly` after early consumer termination and cleanup. Line streams retain blank and final unterminated lines and fail with `LineTooLong` beyond `Process.maxLineLength` (default 1,048,576 characters). `Process.stageDefaults` sets stage defaults overridden by explicit command settings; `Process.renderPlan` prints short lines without executing.

### Axial.FileSystem and Axial.HttpClient

Their flow-valued service members and `FileSystem.test`/`Http.test` doubles are described above; `HttpFactory.live` adapts `IHttpClientFactory`.

### Axial.Hosting

`Axial.Hosting` references Microsoft's systemd and Windows Services Generic Host integrations. `SystemdNotify.live` sends Unix datagrams to an explicitly supplied notification socket. `Hosting.watchdogWith` takes explicit environment variables, process identity, transport, and application health check; it pings only when the runtime heartbeat advances. `Hosting.watchdog` uses the runtime check without an application check. The service hosting guide covers systemd units and Windows SCM recovery; `scripts/check-systemd-watchdog.sh` checks steady operation, SIGKILL recovery, and watchdog timeout with a transient user unit.

### Axial.Guardrails

AXG001 flags blocking waits outside flows (`Async.RunSynchronously`, `Task.Wait`, task/value-task `.Result`, awaiter `.GetResult`) and direct `Flow.run`/`runSync`/`RunSynchronously`/`StartAsTask` calls returning scope-owned `Cache`, `Hub`, or `Queue`. Completed-task results guarded by the same task's completion state and `ContinueWith` continuation parameter results are exempt. Intentional blocking boundaries can use `axial-allow-effect: blocking`. `TimeZoneInfo.Local` is flagged under the PlatformService environment guardrail; supply a time zone explicitly. AXG007 (`ResourceFromFiber`) flags forked flows returning resources they acquired and release before `Fiber.join`. AXG008 flags scoped `Queue.makeScoped`, `Hub.makeScoped`, `Hub.subscribe`, and cache constructors; unscoped `Queue.make` (including shorthands) and `Hub.make` may escape. Only caches are checked through composed result types, because Queue and Hub types do not encode scoping.

## Behaviour changes

- Receiving a concurrent flow's value retains its scoped resources; discarding the value releases them. Scoped resources include `Flow.scopeResource` values and hub subscriptions. `Flow.zipPar`, `sequencePar`, `traversePar`, and `forEachPar` use separate scopes: on success acquisitions move to the caller; on failure all release before return. `Flow.race` retains the successful winner's resources and releases the interrupted loser's. `Flow.timeout`, `timeoutToOk`, and `timeoutWith` release timed-out or failed acquisitions before returning or running fallback.
- `Flow.traversePar` and `forEachPar` retain each item's resources after its worker finishes, rather than releasing them before traversal returns. The per-worker resource of their `...Using` variants still releases when that worker finishes.
- Direct tail-recursive `flow { ...; return! loop () }` runs in constant memory on .NET when completed iterations have no pending work or lexical cleanup. `Flow.bind` and `Flow.delay` trampoline continuations; previously async iterations retained tasks until completion. Fable already used constant memory.
- A process stage deadline starts at stage launch, not topology start.
- On isolated .NET `ScopeCloseBenchmarks` (per 1000 scopes, mean / allocated), release cost changed without changing execution:

| Case | T1b before | T1b after |
| --- | ---: | ---: |
| Empty close | 425.4 μs / 790.55 KB | 411.1 μs / 782.40 KB |
| Acquire/release | 1116.3 μs / 2048.37 KB | 891.7 μs / 1571.47 KB |
| One finalizer | 1166.9 μs / 2103.06 KB | 920.9 μs / 1626.15 KB |

A scope locks on itself, stores one finalizer without a dictionary, and skips the multi-finalizer state machine on .NET and sorting for one finalizer; Fable retains its trampoline. Releases still use a new runtime and scope and switch the ambient runtime: synchronous completion cannot prove the release did not read it. Parallel composition allocations stayed within the pre-T1b range.

## Fixes

- Guardrails findings fail with an `AXG` diagnostic and findings summary rather than an `MSB3073` CLI exit message; other nonzero CLI exits report tool failure.
- On .NET, `App.start` runs the root off the caller's synchronization context. `AppHandle.StopAndWait(timeout)` requests stop and blocks through finalizers or timeout, including on UI threads.
- `FlowStream.ofAsyncEnumerable` creates an enumerator per run and disposes it on early exit. `TQueue` and `TSemaphore` reject non-positive capacity and negative permits. The test file system's `AppendAllLines` appends a newline after each line, matching `System.IO.File.AppendAllLines`.
- Process stream cleanup preserves the original failure cause. Keyed fiber slots drop settled fibers even when they settle immediately. Fable compiles after the Process file split.

## Documentation

- The type troubleshooting guide resolves FS0030 for generic environment flows with a type function rather than a value. The Flow type guide describes constant-memory recursion.
- The scopes guide explains release execution and scoped-resource behavior across concurrency combinators, including a table and a note for ZIO/Effect readers; the fibers guide and `llms.txt` cover it too. Scopes, fibers, semaphore, cache, and supervision examples use `Ref` rather than locks or `Interlocked`.
- The layers guide, tutorial, hosting, and platform-service layers use `Layer.fromFlow`. Process guides cover commands, capture, completion-aware streams, and runners with checked DSL recipes. Long guides were split into focused pages; the docs contain 246 `fsharp run`/`fsharp transcript` example blocks. API enrichment pages were reviewed, and the hand-written `llms.txt` entry points and package maturity page updated.

## Packaging

Project files declare Experimental or Incubating maturity; NuGet descriptions and tags expose it. The package maturity guide lists qualifying real application usage and promotion rules; no package qualifies as Stable yet. The .NET SDK is pinned to 10.0.402 in `mise.toml` and CI workflows.
