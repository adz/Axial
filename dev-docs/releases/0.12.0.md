# Axial 0.12.0

Axial 0.12 strengthens structured concurrency, moves platform services into the runtime, introduces layered configuration, and makes Guardrails a repository-wide architectural policy.

This release also improves cancellation and defect handling throughout Flow, streams, layers and processes, while reducing NativeAOT warnings.

# Highlights

Structured concurrency and reliability

- "Flow.race" now interrupts and awaits its losing branch. "Flow.forkReplacing" waits for the previous fiber to finish before starting its replacement.
- "Flow.disconnect" explicitly allows a caller to stop waiting while retaining ownership of the work at the root run.
- Parallel flows, streams and layers now reliably interrupt and join siblings on failure, preserving concurrent defects.
- Cancellation distinguishes runtime-requested interruption from foreign "OperationCanceledException" defects.
- Fixed hangs and lost cleanup in "Flow.memoize", "Cache", stream operators, "flow { }" exception handling and parallel execution.
- "Fiber.await" becomes "Fiber.awaitExit"; "Fiber.requestInterrupt" adds non-blocking interruption requests.
- "Flow.fold" handles typed failures only; "Flow.foldCause" retains whole-cause handling.

Runtime services and logging

Clock, random, GUID, logging and telemetry are now scoped runtime services rather than application environment requirements.

- Override services with "Flow.withClock", "withRandom", "withGuid", "withLogSink" and "withTelemetry".
- Fiber inheritance and scope restoration are handled automatically.
- "ILogSink" replaces "ILog", with filtering, mapping, teeing and in-memory capture.
- Host adapters integrate logging with Microsoft logging, ASP.NET Core, GenHTTP, Node, Browser and Elmish.
- Tests use deterministic runtime services without constructing service-heavy environments.

Guardrails: architectural policy

Guardrails now uses "Axial.Guardrails.toml" and an approved lockfile instead of relying on scattered suppression comments.

- Assign "domain", "services", "capabilities", "host" and "test" roles to projects and files.
- New rules discourage raw tasks, threads, discarded asynchronous work, unsafe cancellation and catch-all exception handlers.
- Ordinary builds default to fast, non-blocking guidance. Full typed analysis remains available with "AxialGuardrailsMode=Full".
- "axial check --full" provides a complete solution checkpoint, including policy review and coverage verification.
- "axial policy review" exposes policy drift for human approval, with "review --check" supporting CI enforcement.
- Incremental analysis, per-target-framework coverage reports and caching reduce repeated work.

Processes and hosting

"Axial.Process" now uses scoped Flow fibers and a coordinated shutdown lifecycle.

- Process runs own and await stdin feeders, propagating their failures.
- "Process.stopGracefully" provides configurable signal and grace-period escalation before process-tree termination.
- "ProcessStarted.Close" initiates owned shutdown; the new "ProcessStarted.Signal" sends individual signals without escalation.
- Process callbacks expose PIDs and close handles, with corresponding test support.
- Generic Host shutdown waits for application finalizers and reports cleanup that exceeds the host timeout.

Scheduling and parallelism

The new "RunOn" abstraction makes execution placement explicit.

- Choose inline execution, thread pool, dedicated thread, custom scheduler or adaptive scheduling.
- "Flow.runOn" places individual flows.
- "Parallelism.cpu", "io", "blocking" and "adaptive" provide workload presets.
- "Flow.sequenceParWith" combines bounded concurrency with execution placement.
- Fable continues to execute placement choices inline.

Configuration, culture and platform compatibility

- New "Axial.Configuration": layered environment, command-line, JSON, browser and Microsoft configuration sources, with schema-based decoding, validation and optional watching.
- Culture and time zones: explicit values and pure formatting operations, with deterministic defaults in tests.
- NativeAOT: shipped runtime assemblies no longer depend on FSharp.Core's reflection-based "printf" formatter; packable libraries use "--reflectionfree".
- HTTP and WebSocket: improved invalid-request classification, disposal correctness, caller-owned transport configuration and runtime-service propagation.
- FileSystem: atomic file writes use the runtime GUID generator, enabling deterministic testing.

# Breaking changes and migration

0.12 includes significant API changes from 0.11.x.

Area| Required migration
Platform services| Remove "IHasClock", "IHasRandom", "IHasGuid", "IHasLog" and related layers. Use scoped runtime overrides.
Packages| "Axial.PlatformService" is removed; its functionality moves into "Axial" and "Axial.Configuration".
Files| "Axial.Files" is merged into "Axial.FileSystem".
Layers| "Axial.Layers" is removed; use "open Axial".
Logging| Replace "ILog" with "ILogSink" and migrate logging configuration and test sinks.
Environment variables| Replace "IEnvironmentVariables" and typed environment readers with "ConfigSource" and "Config".
Guardrails| Replace legacy suppression settings with TOML roles and an approved policy lock.
Processes| Use "ProcessStarted.Signal" for one-shot signals; "Close" now initiates shutdown.
Fibers| Rename "Fiber.await" to "Fiber.awaitExit".
Error handling| Use "Flow.foldCause" where whole-cause handling is required.
Host adapters| Update Elmish, Generic Host and endpoint logging options and clock configuration.

Additional compatibility changes include "Guid.fromSequence" becoming "Guid.sequence", new "ProcessError" cases, "StageResult.ProcessId", stricter ambiguous Result bindings, and reverse-acquisition resource release in "Layer.zipPar" and "Layer.merge".

Dependencies: Axial 0.12 requires Reified 0.12.1 for configuration schema support, including Fable.

See the migration documentation and individual package APIs for detailed signatures and configuration examples.
