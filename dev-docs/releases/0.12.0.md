# Axial 0.12.0

Structured concurrency now holds at the edges where it used to leak. A flow that starts work waits for it: `Flow.race`
waits for its loser, `Flow.forkReplacing` waits for the fiber it replaces, a process run waits for its stdin feeders,
and the Generic Host waits for the application's cleanup. Where waiting is genuinely wrong, `Flow.disconnect` says so
explicitly, and the work stays owned by the root run. The Process adapter now runs on Flow fibers instead of tasks and
locks, so those guarantees apply to it too.

Guardrails changed from per-line suppression comments to a repository policy: roles for each project and file, a
lockfile that a person approves, and rules that point the other way from raw `Task`, `TaskCompletionSource`, threads and
`CancellationToken.None` back to Flow. Placement of CPU-heavy or blocking work is now a decision you state (`RunOn`).
Cryptographic randomness is a separate service, and the shipped assemblies no longer pull in `printf`, which removes the
NativeAOT warnings it caused.

Guardrails stays open during daily work: policy drift warns, and reasoned suppressions remain active. `axial policy review`
shows what loosened since a chosen commit so a human can review accumulated exceptions instead of approving each edit.
Approval records that reviewed point; `review --check` lets a repository reject later loosening at release or merge time.
The lock is tamper-evident, not a security boundary, and enforcement remains the repository's choice.

## Structured concurrency

Work that outlives the flow that started it is the usual source of leaked resources and lost errors. 0.12 closes the
remaining places where Axial itself did that.

- `Flow.race` now requests cancellation of the losing flow and waits for it to settle before returning. Process
  internals follow the same rule. If work must not be awaited because foreign code may ignore cancellation, wrap that
  specific flow with `Flow.disconnect`; its late result or defect is reported once to the fiber observer. Work started
  with `Flow.disconnect` belongs to the root run (`Flow.run`, `App.start`): the caller stops waiting, but the root
  interrupts the work and waits for it before completing.
- `Flow.forkReplacing` and `Flow.forkReplacingKey` start the new flow only after the replaced fiber has settled and
  released its resources, so the two never overlap. A replacement superseded before it starts never runs. A replaced
  fiber's defect is reported once to the fiber observer instead of being silently marked observed, and
  `FiberSlot.interrupt` and `interruptAll` do the same.
- `FlowStream.mergePar` keeps a defect from a stream that another stream's failure stopped: it is combined into that
  failure, or reported to the fiber observer if it arrives after the failure was delivered.
- `Fiber.await` is renamed `Fiber.awaitExit`, so the name says it returns the fiber's `Exit` as a value. New
  `Fiber.requestInterrupt` asks a fiber to stop without waiting for it; callback exceptions go to the fiber observer, so
  a blocking cancellation callback cannot hold the caller.
- `Flow.runOn` rechecks cancellation when queued work reaches its scheduler, so a flow cancelled while it waited does
  not start.
- `Flow.fold` handles a single typed failure only. Defects and interruption pass through, and typed failures inside a
  compound cause become defects. The previous whole-cause operation is `Flow.foldCause`, whose documentation now says it
  can swallow interruption and defects.
- A new Guarantees page in Concurrency and State states in plain words what Axial promises about finished work,
  interruption, defects and shutdown.

## Processes and hosting

- A process run waits for its stdin feeders. When the program exits or stdin is closed, Axial interrupts the feeder,
  closes the pipe and waits for it to settle. A feeder's failure or defect, including one raised while it stops, is the
  run's failure; interruption and pipe-closed errors are not. A stdin source that ignores interruption keeps the run
  waiting; wrap it in `Flow.disconnect` to return without it. The previous 250 ms bound and background hand-off are
  removed.
- `Axial.Process` executes its live graph as scoped Flow fibers. Every execution starts one queue-driven coordinator that
  owns close requests, timeout and interruption races, and the graceful-stop ladder. Output-cap, pipeline and
  destination failures stop live stages promptly and keep the original failure. The coordinator is no longer cut off 5
  seconds after scope close; it finishes the ladder however long the configured grace periods take.
- `Process.onStarted` reports each stage's PID and a close handle before output is observed. Unix handles support
  SIGINT, SIGTERM, SIGHUP, raw signals and closing redirected stdin; Windows GUI handles support `CloseMainWindow`.
  `Process.stopGracefully` applies one escalation ladder on interruption and timeout before the existing process-tree
  kill. `TestProcess` supplies fake PIDs and records close requests.
- The Generic Host's `StopAsync` waits for the root application and its finalizers. If the host's shutdown timeout
  expires first, it logs that cleanup is still running instead of silently abandoning the wait.

## Guardrails: policy instead of comments

Per-line `axial-allow` comments let each exception be reasonable and the sum of them meaningless. Policy now lives in
one place.

- `Axial.Guardrails.toml` assigns each project and file a role (`capabilities`, `services`, `domain`, `host`, `test`).
  Files default to `domain`. Capabilities may perform ambient effects without suppression comments; elsewhere the
  diagnostic points at an existing Axial service, a service built on capabilities, or a new capability for genuinely raw
  I/O. Rule levels, exact boundary files and the baseline path are read from the TOML.
- `Axial.Guardrails.lock` is a record of the approved policy. A build runs `axial check` first and stops on unapproved
  changes to the policy, protected files, baseline or suppressions. A person runs `axial policy approve`. Lock format
  version 2 identifies suppressions by file, normalized comment text and occurrence number instead of line number, so
  moving a suppression within its file needs no approval, and removing suppressions or shrinking the baseline never blocks checking; summaries list each change on its own line. Optional
  `[suppressions].ignore` globs skip fixture directories.
- New rules steer code back to Flow where the runtime already has a better answer:
  - `AXG009` reports `TaskCompletionSource`, `Task.Run`, `ContinueWith`, thread and `CancellationTokenSource`
    construction outside runtime files and capability bridges. `AXG011` reports `CancellationToken.None` anywhere except
    the runtime's single `Cancellation.never`. `AXG012` reports typed discards of `Task`, `ValueTask` and `Fiber`. All
    three are errors that cannot be suppressed or baselined; exact `[runtime].files` exemptions are protected by the lock.
  - `AXG010` reports catch-all handlers that ignore the exception. It is guidance: it warns, and
    `// axial-note AXG010: <reason>` on the finding's line or the line before turns it into visible Info. Verification
    and release builds set `AxialGuardrailsCheckpoint=true`, which makes unacknowledged guides and invalid notes errors.
  - `AXG013` applies to test code: `Thread.Sleep` is an error; a directly awaited `Task.Delay` or `Async.Sleep` is
    guidance. Replace guessed pauses with a `Deferred` completed at the observation point, wait with a failure
    deadline, or step a test clock. Infinite cancellation waits, bounded `SpinWait.SpinUntil` and the test-support
    `waitUntil` helper are allowed.
  - `lock`, `Monitor` and `Interlocked` are not reported.
- Analysis runs per target framework with that framework's conditional-compilation symbols, so code excluded from a
  multi-target project's first framework is no longer missed. Incremental analysis fingerprints policy, analyzer
  configuration, generated rules and the analyzer and tool binaries by content, so a future-dated cache stamp cannot hide
  a finding. Verification locks cannot be bypassed with an environment variable or inherited by child processes, and
  baseline approval resolves each finding through the file's actual project role.
- The torture-test runner now reports a round that runs longer than 10 seconds. After 60 seconds it prints the live
  fiber tree, interrupts those fibers and fails the round, so a hang names the fibers still waiting.

## Where work runs

Axial starts work inline. Say where CPU-heavy or blocking work runs with a `RunOn`: on one flow with `Flow.runOn`, or on a
parallel batch through its `Parallelism`. Placements include inline, thread pool, dedicated thread, a custom .NET
scheduler and a stateful adaptive learner. `Parallelism.cpu`, `io`, `blocking` and `adaptive` provide workload presets,
and `Flow.sequenceParWith` bounds and places a batch. Parallel combinators still start branches inline unless a branch
opts in; Fable runs every choice inline. The unreleased `Flow.onThreadPool` shorthand was removed.

## Service boundaries and NativeAOT

- `ISecureRandom`, `IHasSecureRandom` and the `SecureRandom` module provide explicit cryptographic randomness for
  secrets, tokens and nonces; `SecureRandom.fromBytes` gives deterministic test data. The `RandomNumberGenerator`
  guardrail now points to it, and the `System.Random` rule warns that `IRandom` is unsuitable for secrets.
- Atomic file writes take their temporary-file names from the explicit GUID service instead of an ambient
  random-number generator, so `Files.writeAtomic`, `writeAllTextAtomic` and `writeAllTextAtomicWithEncoding` now require
  `IHasGuid` as well as `IHasFileSystem`.
- Shipped runtime assemblies no longer reference FSharp.Core's `printf` implementation, which avoids rooting its
  reflection-based formatter and the aggregate `IL2104` and `IL3053` NativeAOT warnings. Every packable library except
  the build-time `Axial.Guardrails` analyzer is compiled with `--reflectionfree`. Types with explicit renderers keep their
  diagnostic text; types without one now use the runtime type name, which changes `ToString()` for public types such as
  `TlsVersion`, `BytesDirection` and `ConnectContext` in `Axial.WebSocket`. The NativeAOT guidance says when applications
  should also use `--reflectionfree`.
- In projects that set `IsAotCompatible=true` or `PublishAot=true`, `AXG006` now reports `sprintf`, `failwithf`, the
  other `printf` functions and interpolated strings with non-string holes. Convert holes to strings or use
  `String.Concat`.
- `WebSocket.invoker` accepts a caller-owned `HttpMessageInvoker`, so applications reuse TLS, certificate, proxy and
  transport configuration without Axial changing it. It cannot be combined with `WebSocket.tls` or
  `WebSocket.connectWith`.

## Breaking changes

- Guardrails no longer recognizes Axial-specific tooling or benchmark paths. Declare host project globs
  under `[exemptions]` in `Axial.Guardrails.toml`, separately for `AXG009`–`AXG012` as needed.
  Existing test-role and runtime-file exemptions are unchanged.

| Before | Now |
| --- | --- |
| Suppression comments and MSBuild settings (`AxialGuardrailsBoundary`, severity, baseline path, test policy) | `Axial.Guardrails.toml` with roles, exact boundary files and baseline path, plus an approved `Axial.Guardrails.lock`. Create the TOML, assign roles, move exact exceptional files to `[boundaries].files`, run `axial policy approve` |
| `axial-allow` for AXG009–AXG013 | No effect, and baselines do not downgrade these rules. Remove the directives; move raw task bridges into capability-role modules; use `axial-note` only for AXG010 and awaited-delay AXG013 |
| Version-1 policy lock | Still readable, but checking is blocked until a person runs `axial policy approve` |
| `Fiber.await` | `Fiber.awaitExit` |
| `Flow.fold` handling whole causes | Handles a single typed failure; use `Flow.foldCause` for the whole cause |
| `Axial.Layers` package, `open Axial.Layers` | Removed; `open Axial` provides `Layer` and `layer { }` |
| `Files.writeAtomic*` needing `IHasFileSystem` | Also need `IHasGuid` |
| `BaseRuntime` without secure randomness | Includes `ISecureRandom`; environments that construct `BaseRuntime` or implement every platform contract must supply `SecureRandom` (`BaseRuntime.liveValue` and `fromServiceProvider` wire it) |
| `StageResult` | Includes `ProcessId` |
| Exhaustive `ProcessError` matches | Handle the new `StopFailed` and `StopUnsupported` cases |
| `Flow.race` returning while its loser cleans up; `forkReplacing` overlapping the replaced fiber; a process run abandoning stdin feeders after 250 ms | Each waits, as described under Structured concurrency; use `Flow.disconnect` for a flow that must not be awaited |
| Binding an `Async<Result<_,_>>` or `ColdTask<Result<_,_>>` with an unknown inner type treated the `Result` as a value | Reports an overload ambiguity. Annotate the inner type, or use `Flow.fromAsyncResult` or `Flow.fromColdTaskResult` |

## Also changed

- `AXG010` counts exception use in guards, assignments, record fields and chained calls; a reporting function's name
  alone does not. It resolves type aliases and ignores narrower typed handlers.
- `AXG012` ignores unit-returning `Async.Start` and `Async.StartImmediate`, recognizes direct and piped `ignore`, and
  leaves awaited work and cold `Flow.fork` descriptions alone.
- `AXG013` no longer exempts infinite `Thread.Sleep` or a tokenless infinite `Task.Delay`, since neither waits for
  cancellation.
- The policy lock no longer hashes Guardrails test sources or project files; `Directory.Build.*`, `.props`, `.targets`,
  analyzer configuration, the TOML, baseline and lock stay protected.
- `flow { }` routes bind sources through one witness-based `Source` and reports clearer environment and error-channel
  mismatches.
- A defect raised alongside a typed process input failure is reported as a defect.
