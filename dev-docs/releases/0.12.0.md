# Axial 0.12.0

Service-boundary fixes for atomic file writes and cryptographically secure randomness, plus NativeAOT formatting changes.

## Breaking changes

- `StageResult` now includes `ProcessId`.
- Layers now ship in the core `Axial` package and `Axial.Layers` is removed. Remove the `Axial.Layers` package reference and `open Axial.Layers`; `open Axial` now provides `Layer` and `layer { }`.
- `Flow.fold` now handles only a single typed failure. Defects and interruption pass through. Compound causes are not
  handled, and typed failures within them are retyped as defects. The previous whole-cause operation is now
  `Flow.foldCause`.
- `Files.writeAtomic`, `Files.writeAllTextAtomic`, and `Files.writeAllTextAtomicWithEncoding` now require
  `IHasGuid` as well as `IHasFileSystem`. Their temporary-file identifiers come from the explicit GUID service
  instead of an ambient cryptographic random-number generator.
- `BaseRuntime` now includes `ISecureRandom`. Environments that construct `BaseRuntime` or implement every platform
  service contract must supply `SecureRandom`; `BaseRuntime.liveValue` and `BaseRuntime.fromServiceProvider` wire it.

## Changed

- Every packable Axial library except the build-time `Axial.Guardrails` analyzer is compiled with F#'s
  `--reflectionfree` option. Types with explicit renderers retain their diagnostic text, while types without an
  override now use the runtime type name instead of a compiler-generated structural representation. This changes
  `ToString()` for public types including `TlsVersion`, `BytesDirection`, and `ConnectContext` in
  `Axial.WebSocket`. The compiler no longer emits generated structured-printing `ToString()` implementations into
  the library assemblies.
- The NativeAOT guidance documents when applications should also use `--reflectionfree` and why applications that
  use FSharp.Core `printf` can still receive the aggregate `IL2104` and `IL3053` warnings for `FSharp.Core`.

## Added

- `Process.onStarted` reports each stage's PID and a close handle before output observation. Unix handles support
  SIGINT, SIGTERM, SIGHUP, raw signals, and closing redirected stdin; Windows GUI handles support
  `CloseMainWindow`. `Process.stopGracefully` applies an escalation ladder on interruption and timeout before the
  existing process-tree kill fallback. `TestProcess` supplies deterministic fake PIDs and records close requests.
- `ISecureRandom`, `IHasSecureRandom`, and the `SecureRandom` module provide explicit cryptographic randomness for
  secrets, tokens, and nonces. `SecureRandom.live` uses the platform cryptography provider, while
  `SecureRandom.fromBytes` supplies deterministic test data.
- The `RandomNumberGenerator` Guardrails rule now uses the `secure-random` category and points to `ISecureRandom`.
  The `System.Random` rule explicitly warns that `IRandom` is unsuitable for secrets.
- `WebSocket.invoker` accepts a caller-owned `HttpMessageInvoker`, so applications can reuse TLS, certificate,
  proxy, and transport configuration without Axial changing it. It cannot be combined with `WebSocket.tls` or
  `WebSocket.connectWith`; byte callbacks are unavailable because the supplied invoker owns the transport stream.
- Guardrails now analyzes each target framework with that framework's conditional-compilation symbols, closing a
  gap where diagnostics such as `AXG006` could miss code excluded from a multi-target project's first framework.
- Shipped runtime assemblies no longer reference FSharp.Core's `printf` implementation. This avoids rooting its
  reflection-based formatter and the resulting aggregate `IL2104` and `IL3053` NativeAOT warnings.
- In projects that set `IsAotCompatible=true` or `PublishAot=true`, `AXG006` now reports `sprintf`, `failwithf`, the
  other `printf` functions, and interpolated strings with non-string holes. Convert holes to strings before
  interpolation or assemble the message with `String.Concat`.
