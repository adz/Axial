# Axial 0.12.0

Service-boundary fixes for atomic file writes and cryptographically secure randomness, plus NativeAOT formatting changes.

## Breaking changes

- `StageResult` now includes `ProcessId`.
- `ProcessError` now includes `StopFailed` and `StopUnsupported`; exhaustive matches must handle the new cases.
- Layers now ship in the core `Axial` package and `Axial.Layers` is removed. Remove the `Axial.Layers` package reference and `open Axial.Layers`; `open Axial` now provides `Layer` and `layer { }`.
- `Flow.fold` now handles only a single typed failure. Defects and interruption pass through. Compound causes are not
  handled, and typed failures within them are retyped as defects. The previous whole-cause operation is now
  `Flow.foldCause`.
- `Files.writeAtomic`, `Files.writeAllTextAtomic`, and `Files.writeAllTextAtomicWithEncoding` now require
  `IHasGuid` as well as `IHasFileSystem`. Their temporary-file identifiers come from the explicit GUID service
  instead of an ambient cryptographic random-number generator.
- `BaseRuntime` now includes `ISecureRandom`. Environments that construct `BaseRuntime` or implement every platform
  service contract must supply `SecureRandom`; `BaseRuntime.liveValue` and `BaseRuntime.fromServiceProvider` wire it.
- `Axial.Guardrails` findings are errors by default. Project-wide severity downgrades are removed; existing findings
  use a checked-in baseline. Suppressions now require a diagnostic ID and reason, work only in files declared with
  `AxialGuardrailsBoundary`, and use forms such as `// axial-allow-AXG001: live service boundary`.
- `Flow.race` now requests cancellation of the losing flow and waits for it to settle before returning. Process
  internals follow the same rule. If work must not be awaited because foreign code may ignore cancellation, wrap that
  specific flow with `Flow.disconnect`; its late result or defect is reported once to the fiber observer.
- `Flow.forkReplacing` and `Flow.forkReplacingKey` now start the new flow only after the replaced fiber has settled
  and released its resources, so the two never overlap. A replacement superseded before it starts never runs. A
  replaced fiber's defect is now reported once to the fiber observer instead of being silently marked observed.
- `Fiber.await` is renamed `Fiber.awaitExit`, so the name says it returns the fiber's `Exit` as a value.
- A process run now waits for its stdin feeders: when the program exits or stdin is closed, Axial interrupts the
  feeder, closes the pipe, and waits for the feeder to settle. A feeder's failure or defect, including one raised while
  it stops, is the run's failure; interruption and pipe-closed errors are not. A stdin source that ignores
  interruption now keeps the run waiting; wrap it in `Flow.disconnect` to return without it. The previous 250 ms
  bound and background hand-off are removed.
- Work started with `Flow.disconnect` now belongs to the root run (`Flow.run`, `App.start`): the caller stops
  waiting, but the root interrupts it and waits for it before completing.
- The `flow { }` builder now routes bind sources through one witness-based `Source`. Binding an
  `Async<Result<_,_>>` or `ColdTask<Result<_,_>>` whose inner type is not yet known reports an overload ambiguity
  instead of silently treating the `Result` as a successful value. Annotate the carrier's inner type when binding a
  plain carrier, or use `Flow.fromAsyncResult` or `Flow.fromColdTaskResult` for a nested `Result`.

## Changed

- `flow { }` reports clearer environment and error-channel type mismatches through its witness-based `Source`.
- `Flow.runOn` now rechecks cancellation when queued work reaches its scheduler, so a flow cancelled while waiting
  does not start.
- `Axial.Process` now executes its live process graph as scoped Flow fibers. Every execution starts one queue-driven
  coordinator that owns close requests, timeout and interruption races, and the graceful-stop ladder, including plain
  one-stage commands. Output-cap, pipeline, and destination failures stop live stages promptly while preserving the
  original failure. User stdin streams run in feeder fibers with only native writes crossing a task bridge, and the
  previous task/lock engine has been removed.
- Every packable Axial library except the build-time `Axial.Guardrails` analyzer is compiled with F#'s
  `--reflectionfree` option. Types with explicit renderers retain their diagnostic text, while types without an
  override now use the runtime type name instead of a compiler-generated structural representation. This changes
  `ToString()` for public types including `TlsVersion`, `BytesDirection`, and `ConnectContext` in
  `Axial.WebSocket`. The compiler no longer emits generated structured-printing `ToString()` implementations into
  the library assemblies.
- The NativeAOT guidance documents when applications should also use `--reflectionfree` and why applications that
  use FSharp.Core `printf` can still receive the aggregate `IL2104` and `IL3053` warnings for `FSharp.Core`.

- `FiberSlot.interrupt` and `FiberSlot.interruptAll` report a defect of the interrupted fiber once to the fiber
  observer instead of discarding it.
- `FlowStream.mergePar` keeps a defect from a stream stopped by another stream's failure: it is combined into that
  failure, or reported to the fiber observer if it arrives after the failure was delivered.
- The Process stop coordinator is no longer cut off 5 seconds after scope close; it finishes the stop ladder however
  long the configured grace periods take.
- The Generic Host `StopAsync` waits for the root application and its finalizers. If the host's shutdown timeout
  expires first, it logs a warning that cleanup is still running instead of silently abandoning the wait.
- `Flow.foldCause` documentation now states that its handler can swallow interruption and defects.

## Added

- A Guarantees page in Concurrency and State states, in plain words, what Axial promises about finished work,
  interruption, defects, and shutdown.
- `Flow.disconnect` lets interruption return without waiting for a specific interruption-insensitive flow. The work
  remains observed, and its late result or defect is reported once to the fiber observer.
- Axial starts work inline. Say where CPU-heavy or blocking work runs with a `RunOn` — on one flow with `Flow.runOn`,
  or on a parallel batch through its `Parallelism`. Placements include inline, thread pool, dedicated thread, custom
  .NET scheduler, and a stateful adaptive learner. `Parallelism.cpu`, `io`, `blocking`, and `adaptive` provide workload
  presets; `Flow.sequenceParWith` bounds and places a batch. The unreleased `Flow.onThreadPool` shorthand was removed.
  Parallel combinators continue to start branches inline unless a branch opts in; Fable runs every choice inline.
- `Fiber.requestInterrupt` requests interruption without waiting for the fiber to settle. Blocking cancellation
  callbacks cannot hold the caller; callback exceptions are reported through the ambient fiber observer.
- `Process.onStarted` reports each stage's PID and a close handle before output observation. Unix handles support
  SIGINT, SIGTERM, SIGHUP, raw signals, and closing redirected stdin; Windows GUI handles support
  `CloseMainWindow`. `Process.stopGracefully` applies one shared escalation ladder on interruption and timeout before
  the existing process-tree kill fallback. Closing stdin returns without waiting for the user input stream, including
  when a pipe write or user cancellation callback does not return; the run itself waits for the stream to settle.
  `TestProcess` supplies deterministic fake PIDs and records close requests.
- `ISecureRandom`, `IHasSecureRandom`, and the `SecureRandom` module provide explicit cryptographic randomness for
  secrets, tokens, and nonces. `SecureRandom.live` uses the platform cryptography provider, while
  `SecureRandom.fromBytes` supplies deterministic test data.
- The `RandomNumberGenerator` Guardrails rule now uses the `secure-random` category and points to `ISecureRandom`.
  The `System.Random` rule explicitly warns that `IRandom` is unsuitable for secrets.
- `WebSocket.invoker` accepts a caller-owned `HttpMessageInvoker`, so applications can reuse TLS, certificate,
  proxy, and transport configuration without Axial changing it. It cannot be combined with `WebSocket.tls` or
  `WebSocket.connectWith`; byte callbacks are unavailable because the supplied invoker owns the transport stream.
- Guardrails now analyzes each target framework with that framework's conditional-compilation symbols, closing a
  gap where diagnostics such as `AXG006` could miss code excluded from a multi-target project's first framework.
- Shipped runtime assemblies no longer reference FSharp.Core's `printf` implementation. This avoids rooting its
  reflection-based formatter and the resulting aggregate `IL2104` and `IL3053` NativeAOT warnings.
- In projects that set `IsAotCompatible=true` or `PublishAot=true`, `AXG006` now reports `sprintf`, `failwithf`, the
  other `printf` functions, and interpolated strings with non-string holes. Convert holes to strings before
  interpolation or assemble the message with `String.Concat`.
